# 使用指南

[文档首页](README.md) · [配置说明](configuration.md) · [图片与表情](media.md) · [记忆管理](memory.md)

机器人只接入配置中的群聊和私聊白名单。管理员的私聊管理命令同样需要通过白名单检查。

## 开始聊天

| 场景 | 使用方式 |
| --- | --- |
| 群聊提问 | @ 机器人、引用机器人的回复，或在文字中叫配置的名称/别名 |
| 私聊 | 从白名单账号直接发送消息 |
| 看图或读字 | 发送图片并说明需求，或引用图片后 @ 机器人提问 |
| 查询图片出处 | 引用图片发送 `/搜图` 或 `/查出处` |
| 指定技能 | 以 `$技能名` 开头，例如 `$text-polish 帮我压缩下面这段话` |
| 开启新的私聊会话 | 单独发送 `/new`；长期记忆仍保留 |

名字和别名出现在消息任意位置都可构成呼叫，但不能紧贴英文字母、数字或下划线。例如别名为 `DemoBot` 时，`demobotpro` 不算呼叫；图片摘要中的名字也不算文字呼叫。

明确呼叫会跳过普通参与模型，但模型仍可根据内容选择沉默。显式技能调用和搜图命令也属于明确请求。

## 命令速查

### 白名单用户

| 命令 | 作用 | 范围 |
| --- | --- | --- |
| `/new` | 重置近期对话上下文，保留长期记忆 | 私聊 |
| `/记忆`、`/记忆 列表 <页码>` | 分页查看可见记忆，每页 30 条 | 群聊、私聊 |
| `/记忆 来源 <ID>` | 查看原消息标识和最短证据 | 群聊、私聊 |
| `/记忆 记住 <内容>` | 保存一条 2～320 字的明确自述 | 群聊、私聊 |
| `/记忆 纠正 <ID> <新内容>` | 建立修订版本 | 群聊、私聊 |
| `/记忆 忘记 <ID>` | 删除修订链与相关派生记忆，屏蔽旧来源 | 群聊、私聊 |
| `/搜图`、`/查出处`、`/查图` | 查询当前或引用图片的来源 | 群聊、私聊 |

记忆的可见范围与修改权限见[记忆管理](memory.md)。英文命令为 `/memory list`、`source`、`remember`、`correct`、`forget`，参数与中文命令对应。

### 管理员私聊

| 命令 | 作用 |
| --- | --- |
| `/model`、`/模型` | 查看模型列表与任务绑定 |
| `/model <名称>` | 切换后续请求的聊天模型及跟随任务 |
| `/skills`、`/技能` | 查看已发现的技能和不可用项 |
| `/表情` | 列出前 30 个可用表情、目录 ID 与总数 |
| `/表情 同步` | 读取 QQ 收藏，新增项目在后台建立描述 |
| `/表情 复核` | 查看最近 10 条自动复核结果，不触发额外模型请求 |
| `/表情 状态` | 查看列表同步与原生收藏上传状态 |
| `/表情 停用 <ID>` | 手动停用并保留原图 |
| `/表情 启用 <ID>` | 启用表情，必要时恢复隔离中的原图 |

表情英文入口为 `/stickers`，对应子命令为 `sync`、`review`、`status`、`disable`、`enable`。表情功能需要先在配置中开启；已清理且没有可用原图的本地项无法直接启用。

## 群聊如何接话

普通群聊先通过规则筛选，再由参与模型读取少量近期文本判断是否接话。明确 @、引用或叫到机器人名称时跳过这一步。

| 情况 | 行为 |
| --- | --- |
| 普通文字话题 | 受考虑间隔、发言冷却、近期发言占比约束，通过判断后才准备完整上下文 |
| 无人呼叫、也不在近期对话中的纯图片、纯表情或纯转发 | 在调用聊天模型前跳过 |
| 明确引用或 @ 别人 | 优先跳过；同时 @ 或叫到机器人名称时仍可处理 |
| 同一用户在近期对话窗口内继续发言 | 先判断是否延续话题；换话题时重新应用普通参与规则 |

普通参与默认每 30 秒考虑一次，连续沉默可退避到 120 秒。任意实际成功回复都会清零沉默计数，并为刚回复的用户刷新 `followup_seconds` 候选窗口，模板为 90 秒。仅收到消息、模型沉默或发送失败不会刷新窗口。

候选窗口内的消息会先绕过普通冷却与参与退避，由参与模型判断话题；只有 `continuation=true` 才按续聊处理。窗口表示值得判断的范围，不代表该用户接下来的所有话都属于同一话题。

## 回复与上下文

群聊每轮只处理一个原消息目标。多人先后明确呼叫时，按接收顺序分别处理，不合并不同人的答案。

一轮可生成 1～3 条消息，首条使用 QQ 原生引用，后续间隔 0.6 秒续发；每段记录仍关联同一个目标。文字与一张表情可以在同一条消息中发送。私聊正文按普通私聊消息发送，内部仍记录目标关联。

上下文优先保留本轮请求、直接引用及最多三层本地引用链，再保留当前用户近期来往，最后补充群聊背景。模板的 `memory.recent_message_limit` 为 8。引用原文随对应历史回复共同参与预算，避免只保留机器人转述。

私聊支持连续输入合并。`/new` 只重置近期对话，不会清空长期记忆；需要删除记忆时使用 `/记忆 忘记 <ID>`。

明确看图请求或单独 @ 后没有附图时，可等待同一发送者补图；批次等待模板为最多 4 秒，关联窗口模板为 90 秒。多图选择、引用链和合并转发的处理见[媒体指南](media.md)。

## 排队与失败提示

每个会话按顺序处理，不同会话共享模型并发。模板限制每会话待处理量为 64、全局为 512；普通候选默认超过 120 秒失效，明确呼叫默认超过 300 秒失效。队满时可替换旧普通候选，未能接收的明确请求会收到限频提示。

群聊的聊天生成或参与判断超时，会引用原消息说明失败阶段和本地期限，包括普通参与判断。明确呼叫、已确认续聊和普通私聊的其他模型或发送失败，在尚未发出正文且结果明确时，也会发送简短提示。后台记忆、表情分析和复核失败只记日志。

模型选择沉默、目标已撤回、上下文已失效、正文已经部分发出或 QQ 发送结果未知时，不补发整轮。每段成功回执单独保存；发送超时或发送中进程退出记为 `unknown`，重启后不会自动重发。普通群消息不会取消正在生成的回复，已撤回的目标会取消。

失败通知按源消息去重，不进入普通聊天上下文或记忆，也不刷新发言冷却与续聊窗口。排查方式见[日志与诊断](../ops/OPERATIONS.md#日志与诊断)。
