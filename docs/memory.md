# 记忆管理

[文档首页](README.md) · [命令速查](usage.md#命令速查) · [配置说明](configuration.md) · [恢复流程](../ops/OPERATIONS.md#恢复流程)

记忆在 NoneBot 进程内运行，使用同一个 SQLite 数据库。后台模型整理有来源的记忆，本地 FastEmbed/ONNX Runtime 使用 CPU 生成向量，不需要额外向量数据库或 embedding API Key。

仓库不附带聊天历史、人物档案、向量索引、遗忘账本或预置记忆。新实例从自己的空数据目录开始，基础人设也不预设私人关系或共同经历。

## 记忆如何建立

后台在空闲时整理同一会话的新发言，模型由 `model_tasks.memory` 选择，留空时跟随当前聊天模型。

| 配置 | 模板值 | 作用 |
| --- | --- | --- |
| `memory.extraction_interval_seconds` | 90 秒 | 后台整理间隔 |
| `memory.extraction_batch_size` | 32 条 | 单次整理的同一会话消息数 |
| `memory.extraction_daily_limit` | 48 次 | UTC 每日记忆模型尝试上限 |
| `memory.evidence_chars` | 240 字符 | 每条来源证据片段上限 |

记录内容包括明确自述、偏好、经历、未完成约定、本群习惯，以及标明为暂时推断的人物印象。稳定人物信息与共同经历分开保存，不将第三人的说法当成本人确认，也不把机器人发言作为用户事实证据。

每条记忆保留主体、参与者、来源作者、原消息键、时间、内容哈希和最短证据。整理不自动导入早期人物档案，也不会仅把最近几行发言直接拼成长久经历。

## 可见范围与召回

| 当前场景 | 可读取的记忆 |
| --- | --- |
| 群聊 | 本群产生的人物记忆与共同记忆 |
| 私聊 | 本人的各来源记录，以及本人参与的共同经历 |

私聊不会载入整个群的人物档案，群聊不能查看私聊或其他群内容。

每轮先提供少量人物记忆，再融合关键词与向量结果补充相关经历，因此短消息也可以获得人物档案。人物印象和经历随时间降权。向量在范围过滤后由数据库工作线程执行余弦相似度精确扫描，适用于当前单实例结构。

默认每个用户在每个来源保留 200 条有效记忆，管理员为 400 条，本群共同记忆为 500 条。达到上限时优先归档较旧的印象，其次经历，再其次其他条目。归档保留记录和来源，但退出正常检索。

## 本地向量

以下是模板中的相关配置，修改时合并到已有 `memory` 段：

```yaml
memory:
  embedding:
    model: BAAI/bge-small-zh-v1.5
    cache_directory: ../cache/embedding-models
    threads: 2
    batch_size: 16
  profile_limit: 4
  retrieval_limit: 10
  context_chars: 2400
  semantic_min_similarity: 0.45
```

模型首次在后台加载，缺少文件时下载到缓存目录，后续复用。下载与推理使用独立工作线程，不占用事件循环。加载失败后约 5 分钟再尝试；模型尚未就绪，或本轮向量计算超过 3 秒时，使用人物档案与关键词召回，并记录原因。

新记忆在后台批量生成向量。写入前重新确认条目仍有效，纠正或遗忘期间完成的旧计算不会重新激活旧记忆。更换本地模型后按模型标识重建向量，不混用不同模型的向量。数据库保存 float32 向量，模型缓存可重新下载，不属于默认备份内容。

## 查看、记住与纠正

白名单用户可用 `/记忆` 查看当前范围的记录，使用 `/记忆 来源 <ID>` 查看证据。只允许修改自己的记忆，或自己提供过来源的本群共同记忆。

```text
/记忆
/记忆 列表 2
/记忆 来源 <ID>
/记忆 记住 <明确自述>
/记忆 纠正 <ID> <新内容>
```

“记住”接受 2～320 字的明确自述。纠正会建立新版本，旧版本退出关键词和向量检索，保留修订关系；旧来源任务不会重新提取同一条旧记忆。

正常聊天中的明确纠正也可通过模型返回的 `memory_updates` 保存，无需另开纠错模型调用。程序要求它引用本轮本人原话和实际提供的记忆编号，检查范围并保存后才发送回复。无法定位或保存时，不发送声称已纠正成功的回复，可改用编号命令处理。

系统区分“以前记错”和“现在发生变化”。历史对话可用于理解变化，但当前有效记忆和本轮明确纠正优先。

## 遗忘

使用 `/记忆 忘记 <ID>` 删除对应修订链、证据和相关派生记忆，并屏蔽旧来源及依赖内容。

遗忘按以下顺序执行：

1. 将消息标识、内容指纹和作用域写入 `state/nonebot/forget-ledger.jsonl` 并同步到磁盘，账本不保存原话。
2. 执行数据库删除与来源屏蔽。
3. 让原消息、引用副本、依赖回复和相关历史摘要退出模型上下文，阻止后台从旧来源再次提取。

生成与发送前会核对记忆版本，尚未交给 QQ 的旧上下文回复会中止。已经交给 QQ 的发送无法通过此流程撤销。命令及其回执不进入普通聊天上下文。

`/new` 仅重置私聊会话，与遗忘不同。日志和历史备份仍按原保留期轮转，不会被遗忘命令立即抹除；屏蔽依据原消息与内容指纹，不能保证识别用户以后所有同义改写。

## 账本、保留与恢复

**当前遗忘账本必须独立保留。** 恢复旧数据库时，需要使用当前账本重新应用备份之后发生的遗忘；旧备份中的账本不能替代当前版本。

账本缺失、损坏或比数据库已应用记录更旧时，启动或恢复会停止。未完成的遗忘会暂停模型上下文使用，需要停止服务后离线恢复账本并重放。不得重建空账本、删除迁移记录或换用跳过检查的旧入口绕过恢复要求。

原始聊天、审计、会话片段与模型用量有各自保留期限；长期记忆及其最短证据不会仅因原消息到期而自动删除。完整规则见[数据保留](../ops/OPERATIONS.md#保留规则)，恢复步骤见[运维指南](../ops/OPERATIONS.md#恢复流程)。
