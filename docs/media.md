# 图片、转发与表情

[文档首页](README.md) · [使用指南](usage.md) · [配置说明](configuration.md)

普通图片在聊天需要时读取；图片出处检索需要明确请求；自动表情收藏只处理平台标记的表情候选。看图与表情分析需要所选模型支持图片输入。

## 看图与多图选择

群聊中可以引用图片后 @ 机器人提问，也可以发送图片并附上需求。私聊使用相同的图片理解流程，支持画面说明、读字和相关追问。

图片按以下顺序选择：

1. 明确引用的图片，以及引用链中关联的原图。
2. 当前消息和同批补充图片。
3. 已关联的上一轮图片。
4. 当前会话最近一条含图消息，仅在出现“识别上图”“看看”“这是什么”等指向时使用。

近期图片窗口由 `group_behavior.recent_window_seconds` 控制，模板为 300 秒；群聊中可以引用其他群友发出的图片。有明确引用时，不会因该引用读取失败而改查附近图片。

明确看图请求或单独 @ 后没有附图时，最多按 `budget.max_batch_wait_seconds` 等待补充，模板为 4 秒。同一会话、同一发送者的关联状态保留 `followup_seconds`，模板为 90 秒；后续图片和澄清会关联原请求，不合并其他人的消息。撤回、遗忘或私聊 `/new` 后，旧来源不可重新注入。

| 情况 | 处理方式 |
| --- | --- |
| 指向单张，但候选消息有多张图 | 先询问第几张或整组 |
| 已进入选图澄清 | 可回答“第 2 张”“最后一张”或“全部” |
| 选择整组图片 | 按原顺序读取，保留原始编号与读取状态 |
| 部分图片缺失或超过上限 | 标明可读取范围，不因缺图改变后续编号 |
| 模型不支持图片 | 标明能力限制，不记成图片下载失败 |
| 原图或引用来源不可用 | 需要重新提供原图 |

整轮图片数由 `model.max_images_per_message` 限制，模板为 8 张，包含引用、补图和转发图片。下载器最多并发读取 4 张，单图最多 8 MiB；动态图理解可能只覆盖部分画面。

普通原图不额外落盘，也不单独启动后台识别。下载器复用连接与在途请求，内存缓存上限为 24 MiB，保留 30 秒。普通看图不会自动反向搜图。

## 合并转发

接收时保存转发 ID 与内联节点，在本轮需要时调用 OneBot `get_forward_msg`，按节点顺序展开说话人、文字和图片。

| 限制 | 每轮上限 |
| --- | --- |
| 嵌套深度 | 3 层 |
| 转发节点 | 60 个 |
| 远端读取 | 8 次 |
| 转发正文 | 12000 字符 |
| 远端读取总时间预算 | 20 秒 |

重复 ID 复用本轮结果。循环引用、读取失败或截断会留下说明；转发里的原话作为聊天内容，不作为程序规则。展开后的图片仍受本轮模型图片上限约束。

## 图片出处检索

### 使用与配置

引用图片发送 `/搜图`、`/查出处` 或 `/查图`，也可带图发送命令。自然语言如“谁画的”“查这张图的来源”“哪部番”在获得回复资格后触发检索；群聊可以用 @ 明确呼叫。

设置 `image_sources.enabled: true`，并按需在 YAML 同目录的 `persona_agent.env` 中填写：

```dotenv
SAUCENAO_API_KEY=replace-with-your-key
SERPAPI_API_KEY=replace-with-your-key
```

没有使用的服务可留空，修改后重启。trace.moe 使用匿名接口。

一次检索一张图片，多图先询问编号，关联窗口内可继续回答“第 2 张”。有明确引用时只查该引用链。尚在选图或等待补图时不扣次数。

### 检索流程与结果

通常先查 SauceNAO；明确问动画时优先 trace.moe。没有合格候选时，再使用 SerpApi 的 Google Lens 同图网页检索。最多返回 3 个去重候选链接及接口提供的相似度或同图标记，直接发送结果，不由模型补写作者、首发时间或链接。

相似度不等于结论正确率，同图网页也可能是转载。无法确认出处时只报告实际检索结果。

检索前使用 Pillow 在内存中转为去除元数据的 JPEG，最长边 1200 像素、最大 500 KB，原图像素数上限为 2000 万。动态图只检索首帧并注明。外部检索服务接收处理后的图片，不接收 QQ 签名链接、聊天正文或用户标识；图片在外部的保存行为由对应服务决定。

### 期限、次数与缓存

| 项目 | 模板值或固定限制 |
| --- | --- |
| 整次检索期限 | `image_sources.timeout_seconds`，45 秒 |
| 全机器人每日检索次数 | `daily_limit`，20 次；0 停用检索 |
| Google Lens 滚动 31 天次数 | `serpapi_31day_limit`，200 次；0 停用该服务 |
| 检索并发与间隔 | 单任务，至少间隔 10 秒 |
| 成功结果缓存 | 10 分钟，最多 64 条 |

本地限额持久化，重启不清零，失败调用也计数。接口失败不自动重试。其他应用对同一服务账号的用量不计入本地统计，实际余量仍以服务商为准。

缓存按会话、记忆版本和图片哈希隔离，命中不扣次数。结果末尾的“今日剩余 X 次”每次重新读取，使用 UTC 日计数，即北京时间每日 08:00 重置。缺图、歧义、限额与超时提示在群聊中引用原消息。

## 表情收藏

### 开启与接入

`stickers.enabled` 在模板中关闭，开启后才运行入库、同步与复核。QQ 原生收藏额外使用 LLBot WebUI 专有接口，需填写 `webui_url` 并自行提供 `webui_token_file`；这些接口不属于通用 OneBot V11。

令牌文件默认指向 `config/llbot_webui_token.txt`，初始化不会生成它，默认备份也不包含它。请在实例中提供文件，不将令牌直接写进 YAML。

后台在启动时及每 10 分钟读取 QQ 收藏。原生上传不可用时，选中的原图保存在 `stickers.directory`，作为全局本地表情库。列表同步成功与上传成功是不同状态，可通过 `/表情 状态` 分别查看。

### 候选与入库

只有下列平台标记会进入后台候选筛选：

- `mface` 或 `marketface`。
- 图片 `subType=1` 或 `sub_type=1`。
- 原生表情 ID。

标记在下载和模型调用前检查。缺少标记的普通图片只保留消息来源引用，不后台下载、识别或收藏。带标记也不保证是表情，模型需同时通过 `is_sticker` 与 `favorite` 判断。

| 配置 | 模板值 | 作用 |
| --- | --- | --- |
| `collect_interval_seconds` | 60 秒 | 每会话新增候选的最短间隔，单条多图也遵守 |
| `max_favorites` | 200 | 达到可用收藏上限后停止自动新增，停用项不占名额 |
| `candidate_limit` | 6 | 每轮可提供给聊天模型的表情候选上限 |
| `upload_retry_seconds` | 1800 秒 | 原生上传失败的起始退避 |
| `upload_retry_max_seconds` | 21600 秒 | 原生上传失败的最长退避 |

已有 QQ 收藏同步不受新增上限限制。收藏不要求同时发言；群聊与私聊共用表情目录，聊天记录仍按会话隔离。

`media_assets` 保存内容哈希、语义、情绪/场景标签、判断理由、QQ 收藏 ID 或本地路径与使用次数。同内容按 SHA-256 复用判断；拒绝项只保存元数据。来源变更可能需要重新下载计算哈希，但不重复调用识别模型。

上传失败状态持久化，读取列表成功不会重置上传失败退避。QQ 收藏被手动删除后会在同步时退出可选目录，本地备用项保留。

### 回复中使用

按当前文字、引用内容、已有媒体语义和紧邻对话选择相关表情；零匹配时不凑数。提示词只包含候选的短语义与标签，允许没有候选。

发送表情后记录媒体关联，不把画面描述拼入机器人正文。同一张表情同时用于聊天和后台入库时，可能分别产生模型调用。入库任务及来源关系持久化，失败最多尝试 3 次，间隔 10 分钟。

## 表情复核与原图清理

开启 `review_enabled` 后，后台每分钟检查是否有空闲处理复核。默认按北京时间每天最多尝试 10 张，失败或暂缓也占次数，重启不重置。新收藏复用入库判断，保留项默认间隔 30 天复核；规则或人设变化可提前。

复核优先检查未复核及旧规则项。库满时，使用记录只影响同等优先级的检查顺序；长期未用不会直接淘汰，也不为腾出数量强行停用。聊天有任务或模型并发已满时不启动复核，已发出的请求不强行取消。

| 结果 | 后续行为 |
| --- | --- |
| 保留 | 继续可用，更新复核时间 |
| 停用 | 立即退出回复候选，但不取消 QQ 原生收藏 |
| 暂缓 | 保持现状，等待后续复核 |

复核优先读取本地原图并核对哈希。网络、文件、识图失败，内容变化或判断不确定时均暂缓；请求期间管理员改过状态时丢弃旧判断。使用次数不作为模型淘汰依据。

自动停用的本地原图在没有有效聊天引用、文件满 24 小时后，由维护脚本移入隔离目录；隔离满 7 天才删除。隔离期内可通过 `/表情 启用 <ID>` 恢复。新消息重新引用隔离素材时会恢复文件，但不自动启用。

管理员手动停用会保留原图，不进入自动清理；手动启用后重新计算复核间隔。关闭自动复核不会撤销已经发生的停用。删除原图后仍保留哈希和淘汰理由，防止再次自动收藏；缺少可用原图的本地项无法直接启用。

完整命令见[管理员私聊命令](usage.md#管理员私聊)，文件隔离、备份与保留规则见[运维指南](../ops/OPERATIONS.md)。
